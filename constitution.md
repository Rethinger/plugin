# Конституция проекта MmmmStoryPlugin

## 1. Основной стек технологий

### Языки программирования:
- **Java 21** - основной язык разработки плагина

### Фреймворки и API:
- **PaperMC API 1.21.x** - серверная платформа для Minecraft
- **Bukkit API** - основной API для разработки плагинов Minecraft

### Сторонние библиотеки:
- **NpcApi-Paper** - библиотека для работы с NPC (версия 1.21.x-4)
- **Maven** - система сборки и управления зависимостями

### Зависимости:
- **Java 21** - минимальная требуемая версия Java
- **PaperMC 1.21.x** - минимальная требуемая версия сервера

## 2. Архитектура и структура

### Основные пакеты:
```
com.mmmm.story/
├── commands/          # Обработчики команд плагина
├── listeners/         # Обработчики событий по актам
│   ├── Act1Listener   # Волны, алтари, сюжетные элементы
│   ├── Act2Listener   # Босс №1 и босс №2
│   ├── Act3Listener   # Край, дракон, кристаллы
│   ├── Act4Listener   # Артефакты в городах Края
│   └── Act5Listener   # Финальный ритуал
├── managers/          # Менеджеры систем
│   ├── ConfigManager  # Управление конфигурацией
│   ├── DataManager    # Управление данными игроков и мира
│   ├── DialogManager  # Управление диалогами
│   ├── ItemManager    # Создание и управление сюжетными предметами
│   ├── NPCManager     # Управление NPC
│   ├── MenuManager    # Управление GUI меню
│   ├── MessageManager # Управление локализованными сообщениями
│   ├── StructureManager # Управление структурами
│   └── PlayerPlacedBlocksManager # Отслеживание блоков, размещённых игроками
└── data/              # Классы данных
    └── PlayerSettings # Персональные настройки игрока
```

### Главный класс:
- **MmmmStoryPlugin** - основной класс плагина, наследующий JavaPlugin
- Использует singleton паттерн через статическое поле instance
- Инициализирует все менеджеры и регистрирует слушателей событий

### Структура ресурсов:
```
src/main/resources/
├── plugin.yml         # Метаданные плагина
├── config.yml         # Основные настройки
├── dialogs.yml        # Диалоги с таймингами
├── messages.yml       # Локализованные сообщения
├── dialogs_en.yml     # Английская локализация диалогов
├── messages_en.yml    # Английская локализация сообщений
└── structures/        # .nbt файлы структур
```

## 3. Управление данными

### Формат хранения:
- **YAML** - основной формат для конфигурации и сообщений
- **Файловая система** - данные сохраняются в папке `data/` внутри папки плагина

### Расположение данных:
- **data/global.yml** - глобальные данные мира:
  - Текущий акт
  - Статусы боссов (побеждены/не побеждены)
  - Статусы порталов (включены/выключены)
  - Количество собранных артефактов
  - Координаты важных локаций
  - Статус финального ритуала

- **data/players/<uuid>.yml** - персональные данные каждого игрока:
  - Список достижений
  - Дата первого входа
  - Текущий акт игрока
  - Персональные настройки (показ диалогов, язык, скорость диалогов)
  - Статус готовности к началу сюжета
  - Оригинальная точка возрождения (для Акта 5)
 - Статус "заперт в Крае" (для Акта 5)

### Управление данными:
- **DataManager** - центральный класс для управления всеми данными
- Автоматическое сохранение каждые 5 минут
- Резервное копирование при сохранении глобальных данных
- Поддержка персональных настроек игроков
- Методы для получения и сохранения настроек игроков
- Методы для отслеживания прогресса по актам

## 4. Особые практики

### Локализация:
- Поддержка многоязычности (в настоящее время русский и английский)
- Персональные настройки языка для каждого игрока
- Централизованное управление через MessageManager

### Система меню:
- GUI-меню для настроек и просмотра прогресса
- Поддержка навигации между меню
- Проверка состояния игрока (в бою, в диалоге) перед открытием меню

### Система сюжетных предметов:
- Все сюжетные предметы имеют уникальные NBT-теги для идентификации
- Защита от потери при смерти
- Уникальные имена и описания
- Поддержка локализации

### Система диалогов:
- Поддержка интерактивных и автоматических диалогов
- Настройка скорости диалогов для каждого игрока
- Поддержка различных способов отображения (ActionBar, Title, Chat)

### Безопасность:
- Проверка прав доступа для команд
- Защита от спама и злоупотреблений
- Ограничение количества мобов на игрока
- Проверка дистанции перед выполнением ресурсоемких операций

### Производительность:
- Асинхронное выполнение длительных операций
- Оптимизация партиклов и эффектов
- Кеширование загруженных конфигураций
- Ограничение количества активных задач

### Соглашения о коде:
- Использование PascalCase для классов
- Использование camelCase для методов и переменных
- Использование UPPER_SNAKE_CASE для констант
- Документирование методов с помощью JavaDoc
- Использование BukkitRunnable для задержек и повторяющихся задач
- Централизованное управление через менеджеры
- Поддержка персональных настроек игроков
- Идемпотентность операций (безопасная перезагрузка и восстановление состояния)
