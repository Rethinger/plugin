# История изменений - Mmmm Story Plugin

## Версия 1.3.1 - Критические исправления ошибок (7 историй пользователя)

**Дата выпуска**: 24 октября 2025  
**Тип**: Bugfix Release (критические исправления)

### 🐛 Исправленные ошибки

#### Bug #1 (P0): Локализация сообщений обыска сундуков
- **Проблема**: При выборе русского языка сообщения обыска сундуков не переводились
- **Решение**: 
  - Улучшен механизм fallback в MessageManager.getMessage(): ru → en → raw key
  - Заменены все hardcoded сообщения на локализованные ключи в ChestSpawnManager
  - Добавлены ключи chest.search.* в messages_ru.yml и messages_en.yml
- **Файлы**: MessageManager.java, ChestSpawnManager.java
- **Тестирование**: Русский клиент → обыск сундука → проверка русских сообщений

#### Bug #2 (P0): Локализация названий предметов
- **Проблема**: Ключ призыва Повелителя Скелетов показывал "[Missing message: items.boss1_summon_key.name]"
- **Решение**: 
  - Аудит всех ItemManager.createXxx() методов для проверки PDC ключей
  - Подтверждена корректность всех ключей items.* в messages_ru.yml и messages_en.yml
  - Fallback mechanism теперь возвращает raw key вместо ошибки
- **Файлы**: MessageManager.java, ItemManager.java (audit)
- **Тестирование**: Получить Boss1 Summon Key → проверить русское название

#### Bug #3 (P1): Остановка босса перед атакой черепами
- **Проблема**: Повелитель Скелетов не останавливался перед кастом черепов, игроки не успевали в безопасные зоны
- **Решение**: 
  - Boss AI отключается (setAI(false)) на 5 секунд перед атакой
  - Скорость обнуляется (setVelocity(0,0,0))
  - Локализованное предупреждение boss1.wither_skull_attack.warning
  - Конфигурация: freezeBossDuringCast: true, freezeDurationSeconds: 5
- **Файлы**: Act2Listener.java, config.yml, messages_*.yml
- **Тестирование**: Призвать босса → подождать атаки → проверить остановку на 5 секунд

#### Bug #4 (P1): Улучшенная видимость безопасных зон
- **Проблема**: Зоны спавнились на одном уровне с боссом по Y, под потолком их не было видно
- **Решение**: 
  - Новый метод findHighestSolidBlock() для правильного определения земли
  - Обнаружение потолка findCeiling() - зона поднимается над потолком
  - Частицы изменены: 2D круг → 3D сфера (Fibonacci sphere algorithm)
  - Добавлены эффекты: END_ROD (вертикальный луч), GLOW (свечение)
  - Конфигурация: improvedVisibility, beaconEffect, sphereParticles
- **Файлы**: SafeZone.java, config.yml
- **Тестирование**: Босс в Nether Fortress → проверить видимость зон под потолком

#### Bug #5 (P1): Предотвращение взрывов черепов
- **Проблема**: Черепа иссушителя взрывали блоки (хотя setYield(0) был установлен)
- **Решение**: 
  - EntityExplodeEvent handler с приоритетом HIGHEST
  - event.blockList().clear() и event.setCancelled(true)
  - Ручной расчёт урона игрокам с проверкой безопасных зон
  - Множитель урона 2.0x, эффект иссушения уровня 2
  - Подтверждено: setYield(0f), setIsIncendiary(false), setCharged(false)
- **Файлы**: Act2Listener.java
- **Тестирование**: Атака черепами → проверить отсутствие разрушения блоков

#### Bug #6 (P2): Удаление спавна алтаря артефактов
- **Проблема**: Структура dragon_loot появлялась в Краю после смерти дракона
- **Решение**: 
  - Удалены вызовы placeStructure("dragon_loot") в Act3Listener
  - Артефакты теперь получаются только через End City сундуки
  - Добавлены комментарии объясняющие удаление
- **Файлы**: Act3Listener.java
- **Тестирование**: Убить дракона → проверить отсутствие dragon_loot структуры

#### Bug #7 (P2): Очистка маленьких NPC посланников
- **Проблема**: Маленький посланник оставался на спавне после завершения сюжета
- **Решение**: 
  - Улучшен метод NPCManager.cleanup() с проверкой messenger NPCs
  - Добавлен try-catch для безопасного удаления
  - Cleanup() вызывается при завершении Act 5 в Act5Listener
  - Логирование удалённых NPC для отладки
- **Файлы**: NPCManager.java, Act5Listener.java
- **Тестирование**: Завершить сюжет → проверить отсутствие NPC на спавне

## Версия 1.3.0 - Улучшения системы историй и исправления (4 истории пользователя)

### ✨ Новые функции

#### US1 (P1): Многоязычная поддержка предметов
- **Описание**: Автоматический перевод названий и описаний предметов при смене языка клиента
- **Реализация**: 
  - Хранение ключей локализации в PDC предметов (nameKey, loreKeys)
  - Обработчик события PlayerLocaleChangeEvent для автоматического обновления
  - Интеграция MessageManager для всех сюжетных предметов
  - Поддержка русского и английского языков
- **Предметы**: Stabilization Core, Boss Materials, End Artifacts (1-5)
- **Тестирование**: Смена языка клиента через F3+T → Options → Language

#### US2 (P1): Точная синхронизация исчезновения Посланника
- **Проблема**: Посланник исчезал слишком поздно (жёсткий таймаут 58с)
- **Решение**: 
  - Динамический расчёт времени диалога с учётом скорости чтения
  - Точное планирование исчезновения по строке "*Посланник исчезает в тумане*"
  - Методы calculateDialogDuration() и scheduleMessengerDespawn()
  - 5-секундная анимация сжатия NPC
- **Конфигурация**: Время диалога адаптируется к множителю скорости игрока
- **Тестирование**: Диалог messenger.spawn, проверка исчезновения через 63 секунды

#### US3 (P2): Сложный и честный бой с Повелителем Скелетов
- **Тошнота лучников**: Лучники в фазе 2 применяют тошноту 127 уровня на 10 секунд
- **Обнаружение бега по кругу**: 
  - Отслеживание круговых движений на расстоянии 2-3 блока
  - Телепортация эксплуататора на босса после 10 изменений угла за 3 секунды
  - Класс CircleStrafeTracker для анализа паттернов
- **Атака черепами иссушителя** (только фаза 1):
  - Атака каждые 30 секунд с 6-8 безопасными зонами
  - Круговой залп из 16 черепов
  - Красные частицы показывают безопасные зоны (радиус 1 блок)
  - Двойной урон вне зон, нулевой урон внутри
  - Черепа не разрушают блоки и не атакуют скелетов-воинов
  - Классы BossAttackState и SafeZone для управления
- **Конфигурация**: `acts.boss1.phase2`, `circleStrafeDetection`, `witherSkullAttack`
- **Тестирование**: Бой с боссом в обеих фазах, проверка всех механик

#### US4 (P2): Защита End-портала от повреждения
- **Проблема**: Портал заменялся на end_stone после смерти дракона, структуры артефактов появлялись над порталом
- **Решение**: 
  - Автоматическая защита портала при смерти дракона
  - BlockPhysicsEvent (HIGHEST) предотвращает замену блоков портала
  - BlockPlaceEvent (HIGHEST) предотвращает размещение end_stone рядом
  - Структура dragon_loot перемещена на безопасное расстояние (15 блоков)
  - Радиус защиты 10 блоков вокруг портала
- **Тестирование**: Победить дракона, проверить целостность портала и отсутствие структур над ним

### 🔧 Техническая реализация

## Версия 1.2.0 - Критические исправления ошибок (5 багфиксов)

### 🐛 Исправленные ошибки

#### Bug #4 (P1): Блокировка портала End в Актах 4-5
- **Проблема**: Игроки могли сбежать из End через портал до завершения ритуала
- **Решение**: Портал блокируется в начале Акта 4, разблокируется после ритуала в Акте 5
- **Обратная связь**: Частицы SMOKE, звук, сообщение, диалог при попытке использовать портал
- **Конфигурация**: `act4.portalBlocking.*` - включение, эффекты, звуки
- **Тестирование**: `/story skip 4`, попытка пройти через портал, завершение ритуала

#### Bug #5 (P1): Управление точками возрождения в Актах 4-5
- **Проблема**: Игроки могли возродиться вне End, нарушая сюжетную изоляцию
- **Решение**: Точка возрождения сохраняется при входе в End, игрок принудительно возрождается в End до ритуала, восстанавливается после
- **Механика**: Автосохранение при активации ловушки, принудительное возрождение в End, восстановление после ритуала
- **Конфигурация**: `act4.spawnManagement.*`, `act5.ritual.restoreSpawnsOnComplete`
- **Тестирование**: Умереть в End во время Актов 4-5, проверить возрождение в End, завершить ритуал, проверить восстановление

#### Bug #1 (P2): Защита рамок портала End
- **Проблема**: Игроки могли заменить рамки портала на End Stone, нарушая сюжетную структуру
- **Решение**: Рамки портала защищены от размещения/разрушения блоков с высоким приоритетом (HIGHEST)
- **Обратная связь**: Отмена события, звук ENTITY_ITEM_BREAK, частицы SMOKE
- **Автоматика**: Регистрация рамок при загрузке мира End (радиус 20 блоков от 0,50,0)
- **Тестирование**: Попытка разрушить/заменить рамки портала End

#### Bug #2 (P2): Телепортация босса #1 за игрока в Фазе 2
- **Проблема**: Босс был слишком пассивен, игроки могли стоять на месте и атаковать
- **Решение**: В Фазе 2 босс телепортируется за игрока после 3 секунд близости (≤3 блоков)
- **Механика**: Отслеживание близости, кулдаун 10 секунд, поиск безопасной локации (попытки под разными углами)
- **Эффекты**: Частицы PORTAL, звук ENDERMAN_TELEPORT, сообщение игроку
- **Конфигурация**: `acts.boss1.teleport.*` - дистанции, задержки, кулдаун, интервал проверки
- **Тестирование**: `/story skip 2`, довести босса до 50% HP (Фаза 2), стоять близко 3+ секунды

#### Bug #3 (P3): Очистка союзников-эндерменов после смерти дракона
- **Проблема**: Модифицированные эндермены с эффектами оставались после смерти дракона
- **Решение**: Эндермены-союзники помечаются тегом `story_dragon_ally`, удаляются/возвращаются к ванильному поведению при смерти дракона
- **Спавн**: 5 эндерменов при 50% HP дракона с эффектами (Speed I, Strength I)
- **Очистка**: Удаление или возврат к ванильному состоянию (настраивается)
- **Конфигурация**: `acts.end.dragonFight.endermanAllies.*` - количество, эффекты, поведение при смерти
- **Тестирование**: `/story skip 3`, довести дракона до 50% HP, убить дракона, проверить очистку

## Версия 1.0.0 - Система динамического спавна в ванильных структурах

### Крупные изменения

##### ChestSpawnManager - Динамический спавн предметов
- **Ядро Стабилизации** спавнится в сундуках разрушенных порталов
  - Задержка: 5-20 секунд после открытия сундука
  - Шанс: 5% на каждый уникальный сундук
  - Определение структуры: поиск Crying Obsidian и Gold Block в радиусе 20 блоков

- **Фрагмент Гнева (Boss 1 Material)** спавнится в сундуках Крепостей Нижнего мира
  - Задержка: 5-20 секунд
  - Шанс: 5%
  - Определение структуры: Nether Bricks в радиусе 30 блоков

- **Катализатор Пустоты (Boss 1 Catalyst)** спавнится в сундуках Бастионов
  - Задержка: 5-20 секунд  
  - Шанс: 5%
  - Определение структуры: Blackstone и Gilded Blackstone в радиусе 30 блоков

##### Механика обыска сундуков 🔍
**Визуальная обратная связь для игроков:**
- При открытии сундука в нужной структуре появляется сообщение "🔍 Обыск сундука..."
- Показывается название искомого предмета
- Периодические сообщения в action bar "🔍 Обыскиваю сундук..."
- При находке: заголовок "✓ УСПЕХ!", звуковые эффекты, частицы
- При неудаче: сообщение "✗ В этом сундуке ничего не найдено"

**Система отслеживания найденных материалов:**
- После находки материала в структуре, механика обыска отключается для ВСЕХ сундуков этого типа структуры
- Пример: Нашли Фрагмент Гнева в одной Крепости → обыск больше не работает ни в одной Крепости
- После победы над Boss 1 флаги сбрасываются → можно снова искать материалы в Крепостях и Бастионах
- Каждая структура отслеживается независимо (Разрушенные порталы, Крепости, Бастионы)

**Группировка сундуков по структурам:**
- Сундуки группируются по координатам (округление до 50 блоков)
- Все игроки, обыскивающие сундуки в одной структуре, получают уведомление при находке
- Предотвращает множественный спавн одного и того же предмета

##### Boss Bar для Boss 1 ⚔
**Интерактивный Boss Bar:**
- Заголовок: "⚔ Повелитель Скелетов ⚔" (красный цвет)
- Автоматическое обновление здоровья каждые 0.5 секунды
- Мгновенное обновление при получении урона
- Автоматическое отображение/скрытие для игроков в радиусе 100 блоков
- Автоматическое удаление при смерти босса

**Визуальные детали:**
- Цвет: RED (красный)

- Динамическая полоса прогресса от 100% до 0%
